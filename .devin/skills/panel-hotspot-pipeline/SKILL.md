# Panel & Hotspot Pipeline (Switch 320)

ท่อนี้แปลง "PDF ดีไซน์จาก Canva + DOCX คำอธิบายจากลูกค้า" เป็น "รูปแผง + พิกัดปุ่มที่กดได้"
ทุกขั้นเป็นสคริปต์ รันซ้ำได้ผลเดิม เพราะ `data/panels/*.json` เป็น generated artifact ห้ามแก้มือ

## ลำดับคำสั่ง

```bash
python scripts/build-panel-images.py        # PDF -> assets/panels/*.webp (+ แก้จุดที่ประกาศไว้)
python scripts/sync-image-size.py           # อัปเดต imageSize ให้ตรงไฟล์จริง
python scripts/extract-control-figures.py   # ดึงรูปโคลสอัพต่อ control จาก .docx
python scripts/detect-buttons.py <panel>    # ตรวจจับตำแหน่งปุ่มจากภาพ (read-only)
python scripts/place-hotspots.py <panel>    # เขียนพิกัดลง JSON
npm run validate:data && npx tsc --noEmit && npx expo export -p web
```

## ความจริงของไฟล์ต้นทาง (วัดแล้ว ไม่ใช่เดา)

| PDF | ตัวหนังสือ vector | ผลต่อการทำงาน |
|---|---|---|
| Overhead | 543 คำ | หาพิกัดจากป้ายได้ |
| Center Pedestal | **0 คำ** | ต้องอ่านจากภาพเอง |
| Instrument | **0 คำ** | ต้องอ่านจากภาพเอง |

**ห้ามรับไฟล์ PNG/JPG จากลูกค้าเป็นต้นทาง** — ต้องเป็น PDF เท่านั้น เพราะ PNG ไม่มีทั้งตัวหนังสือ
vector และพิกัดรูปย่อย ซึ่งเป็นข้อมูลที่ท่อนี้ใช้ทั้งหมด

## กฎเหล็ก 5 ข้อ (เคยพลาดมาแล้วทุกข้อ)

1. **สัดส่วนรูปต้องตรงกับ `imageSize` เดิม ถ้า panel นั้นวาง hotspot ไปแล้ว**
   hotspot เก็บเป็น ratio 0..1 ถ้าสัดส่วนเปลี่ยน พิกัดทุกจุดเลื่อนพร้อมกันโดยไม่มีอะไรฟ้อง
   `sync-image-size.py` จะบล็อกให้เองเมื่อเจอเคสนี้ (ต้องใส่ `--force` จึงจะข้ามได้)

2. **`npx tsc --noEmit` ผ่านไม่ได้แปลว่า build ได้**
   `require()` ของ asset คืน `any` ทำให้ path ที่หายไปไม่ถูกจับ ต้องรัน `npx expo export -p web`
   ทุกครั้งที่แตะไฟล์ใน `src/` หรือ `assets/panels/`

3. **แก้ pixel บน .webp ต้องประกาศใน `PATCHES` ของ build-panel-images.py**
   ไม่งั้น re-render รอบหน้าการแก้จะหายเงียบ ๆ (PDF เป็น source of truth)

4. **ห้ามลบ/แก้สีที่เป็นข้อมูลการบิน**
   เคสจริง: ลบกรอบแดงอธิบายบนรูป PFD แล้วแถบ VMAX/VLS สีแดงจริงหายไปด้วย
   ต้องคัดด้วย "แดงสดจัด + เป็นเส้นตรงยาวเกิน 200px" และกันโซนที่มีสัญลักษณ์จริงไว้ทั้งโซน

5. **ปล่อย `hotspot: null` ดีกว่าเดา**
   null = ไม่ render ปุ่มนั้น (validate รายงานเป็น warning) แต่ถ้าเดาผิด ผู้ใช้กดโดนปุ่มผิดตัว
   โดยไม่มีอะไรฟ้อง ซึ่งแย่กว่าในงานสอนการบิน

## 3 ชั้นการวาง hotspot เรียงตามความแม่น

**ชั้น 1 — ตรวจจับปุ่มจากภาพ + จับคู่ป้าย vector**
ปุ่มมี 3 แบบ ต้องตรวจ 3 รอบ (วัดจาก overhead.webp): ปุ่มกด `#262E53` เข้ม /
FIRE+การ์ดแดง `#D13C17` อิ่มสี / ลูกบิด `#DEE4F2` สว่างกว่าแผ่นพื้น `#A0AECC`
รอบเดียวด้วยความสว่างจับได้แค่ปุ่มกด ตกลูกบิดกับปุ่มฉุกเฉินหมด

**ชั้น 2 — ไฟแจ้งเตือน = ครึ่งบนของปุ่มแม่**
บน A320 ปุ่มกดหนึ่งปุ่มแบ่งครึ่งบนเป็นไฟ (FAULT/SMOKE/OPEN) ครึ่งล่างเป็นป้ายชื่อ
เอกสารแยกเป็นสองรายการติดกัน (ปุ่มมาก่อน ไฟตามมาทันที) จับคู่จากลำดับในเอกสารได้เลย
ใช้ได้เฉพาะ control ที่อยู่ **ติดกัน** — ไล่ย้อนหลายตัวจะข้ามโซนไปวางผิดที่

**ชั้น 3 — วางจากตำแหน่งป้าย vector**
ป้ายอยู่เหนือตัวควบคุมเสมอบนแผงนี้ ถ้ามีปุ่มที่ตรวจเจออยู่ใต้ป้ายพอดีให้ snap เข้ากรอบจริง

## กับดักการจับคู่ชื่อ

* **ตัดคำสถานะออกก่อนเทียบ** (`FAULT OFF ON AVAIL ALIGN AUTO NORM OPEN SHUT LO HI`)
  ไม่ตัด → `oh_fault_light` ไปโดน 48 ปุ่มรวด เพราะเกือบทุกปุ่มมีคำ FAULT พิมพ์อยู่
* **คำว่า light ไม่ได้แปลว่าไฟ** — `OVHD INTEG light knob` / `ANN Light switch` เป็นตัวควบคุม
  คัดออกด้วยคำ `KNOB|SWITCH|SELECTOR|BUTTON`
* **ตรวจการทับก่อนเขียนทุกครั้ง** — เอกสารมี `MODE SEL push button` สองรายการแต่ป้ายบนรูปมีจุดเดียว
  ถ้าไม่กัน จะวางทับกัน 100%
* **1 รายการในเอกสาร = ปุ่มจริงหลายปุ่ม** เช่น `DISCH` มี 7 ปุ่ม, `ADR 1/2/3` มี 3 ปุ่ม
  schema เก็บได้จุดเดียว จึงวางบนปุ่มตัวแทน แล้วรายงานปุ่มพี่น้องที่ถูกข้าม

## ความละเอียดรูป: อย่าไล่ตามเลขสูงสุด

| render | ไฟล์ WebP | bitmap ในแรมตอนแสดงผล |
|---|---|---|
| 3438×3124 | 0.55 MB | 43 MB |
| 6876×6248 | 0.87 MB | **172 MB** ← เสี่ยง OOM บน Poco X7 |

เพดาน `GL_MAX_TEXTURE_SIZE` ของ GPU มือถือคือ 4096-8192px เกินกว่านั้น Android ย่อรูปเองเงียบ ๆ
= เสียแรมฟรีโดยไม่ได้ความคมกลับมา ตัวที่แก้ปัญหาอ่านตัวอักษรตอนซูมลึกคือ `detailImage`
(รูปโคลสอัพจริงต่อปุ่ม ไฟล์เล็กแยกใบ) ไม่ใช่การดันความละเอียดรูปแผง

`expo-image` ต้องใส่ `allowDownscaling={false}` กับรูปที่อยู่ในกล่องเล็กแต่ถูกซูมด้วย transform
ของ parent ไม่งั้นมันจะ decode เท่าขนาด layout แล้วเบลอตอนซูม

## เอกสารลูกค้าเป็นแหล่งข้อมูลเดียว

* ข้อความทุกตัวอักษรมาจาก .docx ห้ามแต่ง ขยาย สรุป หรือแปล ถ้าไม่ครบให้ `needsReview: true`
* เอกสารวางรูปโคลสอัพไว้ **เหนือหัวข้อของปุ่มนั้นเสมอ** และ control มี `sourceRef` เป็นเลขย่อหน้า
  จึงจับคู่รูปกับ control ได้แน่นอนด้วยลำดับ ไม่ต้องเดาจากชื่อ (ทดสอบกับ glareshield ได้ 23/23)
* ลูกค้ากำหนด: กล่องคำอธิบายเป็น **text only** ห้ามมีรูป — `detailImage` คนละที่กัน
  (มันคือรูปที่ปะบนตัวปุ่มบนแผง ไม่ใช่ในกล่องคำอธิบาย)
